# 状态恢复

在当前项目收集以下信息（只读操作，不修改任何东西）：

1. **进度文件**：读 `PROGRESS.md`。若不存在，说明项目未初始化 harness，直接建议运行 `/autonomy-harness:harness-init` 并结束。
2. **git 状态**：`git log --oneline -15` 看最近做了什么；`git status --short` 看有无未提交的改动（未提交改动 = 上次会话可能中断在半路，要重点分析这些改动处于什么状态）。
3. **验证现状**：存在 `.harness/verify.sh` 则运行一次，得到当前是绿是红。
4. **交叉核对**：PROGRESS.md 声称的状态与 git 历史/验证结果是否一致。不一致时以实际证据为准，并指出进度文件已过时。

## 汇报格式（先结论后细节）

```
## 现在在哪
（一两句话：项目整体处于什么阶段，验证是绿是红）
## 上次进展
（最近完成的 2-3 件事，来自 git log 与 PROGRESS.md）
## 下一步
（明确的单个建议动作，并给出可直接复制的命令形式，例如
 `/autonomy-harness:closed-loop 完成消息撤回功能` 或 `/autonomy-harness:ship`；
 绝不罗列多个选项让用户挑）
## 卡点/风险
（未提交的半成品、失败的验证、过时的进度文件等；没有就写"无"）
```

若发现 PROGRESS.md 与实际不符，汇报后顺手更新它（这是唯一允许的写操作），并说明改了什么。
